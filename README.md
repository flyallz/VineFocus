# VineFocus v1.7.3 · 四边花簇与界面收敛版

VineFocus（花藤专注）是一款使用 Python 与 PySide6 开发的 Windows / macOS 桌面专注工具。v1.7.3 延续高保真细分器官与连续密度控制，并把最重要的反馈落实为可见变化：每轮专注都会长枝叶；每次确认“本轮目标有推进”，会在已生长且稳定随机的新区域舒展一组符合主题习性的花。环屏四段同步成熟，不再先把左上角长满；本轮结果仍由用户明确选择，避免无意推进开花。

## 本版实现

- 默认采用“夜色流光”玻璃感界面，另有“温室晨雾”和“薄荷汽水”。
- 本轮任务默认以摘要卡展示，需要修改时再展开编辑，减少主界面信息压力。
- 四套植物：月白花藤、樱雾花枝、流苏紫藤、极光荧藤。
- 三种布局：静谧单株（默认）、侧边攀援、环屏生长。
- 主藤路径轻微越出屏幕边界；环屏采用四段断续、不对称的贴边构图，不形成压迫感强的完整相框。
- 四套植物各拆为 13 类透明器官：短枝、弯枝、分叉、四级叶龄、卷须、两级花苞、半开、盛开和落瓣，共 52 个正式组件。
- 正式渲染采用“连续 QPainter 主藤 + 独立高清器官”的方案；各节点依次长枝、展叶、结苞、开放，不再裁切或淡入整株完成图。
- 侧枝先以连续曲线伸展，主藤随后覆盖枝根接缝，端叶再遮住枝梢；木质枝段只保留为低透明纹理，解决截断枝、悬挂粗管和关节堆叠。
- 每类器官按真实根部连接：普通叶柄使用左下锚点，极光心形叶与紫藤复叶使用上端悬垂锚点，花苞/花朵使用花梗锚点；镜像时同步修正局部生长轴。
- 每段完成的主藤使用嫩叶收梢；标准和茂盛档增加第二片端叶，部分主题在茂盛档增加顶端花苞，不再裸露圆头断面。
- 枝叶密度使用 0～100 连续滑动条，并标注清爽、标准、茂盛三个语义区间；密度只负责器官数量和成对叶概率，植物尺寸、透明度保持独立。
- 侧边攀援的主藤固定在约 16～72 个逻辑像素的边缘安全带，2K、4K 和超宽屏不会按屏幕宽度比例漂入内容区。
- 高 DPI 尺寸采用封顶缩放，4K/Retina 不再把枝叶随像素数线性放大；叶片方向放宽为稳定的不规则分布，花苞/花位附近自动留出关节空间。
- “夜色流光”改为低饱和石墨蓝、雾面卡片、柔和青绿渐变和跨平台层级投影；关闭玻璃效果时仍可使用更实的表面。
- 组件直接取自冻结概念稿并保留原始自然配色；资源异常时才自动退回旧版绘制，不会因素材缺失而无法启动。
- 每轮完成的专注都会推动枝叶生长；“本轮目标有推进”会在新区域舒展一组花。月白、樱雾、极光一次呈现多朵，紫藤一次呈现一串花序；界面只说“目标推进”，不暴露内部花簇计数。
- 环屏四条断续路径共享同一条成长时间轴，前四次推进稳定随机地落在四段不同区域；休息时花朵约 5.5% 呼吸、枝叶约 2° 轻摆，并由独立低频计时器维持。
- 主面板高度严格跟随当前可见内容，任务编辑展开/收起后自动收敛；卡片植物与桌面花藤使用完全一致的真实成长进度。
- 托盘菜单独立声明前景色与背景色并跟随界面主题，修复浅色系统菜单上的白底白字。
- 极光荧藤直属叶统一朝向屏幕内容区，并加大枝、苞、花附近的连接净距，不再生成同锚点反向叠叶。
- 成果数据默认折叠且完全可选；它只用于统计字数、页数、题数等，不参与花朵数量计算，并在看板汇总所有已填写记录。
- 主面板内嵌同源植物水印；设置页使用可预览主题卡；成长看板包含植物主视觉、环形进度、关键指标、柱线趋势、内容分布与产出卡片。
- 首次启动向导会闭环选择节奏、植物与构图；主面板、设置、产出记录、看板、迷你计时器和托盘/菜单栏均复用已有实例。
- 迷你计时器默认是 52px 植物圆点，悬停展开时间与暂停按钮。
- 第二次启动只唤醒首个实例，不创建第二套窗口或托盘图标。
- 托盘恢复按“清除最小化 → 修正到可见屏幕 → 显示 → 置前 → 激活”执行。
- 多显示器可选择跟随主面板、主显示器或具体显示器；外接屏断开后自动回到主屏。
- Windows 全屏应用位于前台时暂时隐藏花藤，退出全屏后恢复。
- 每 5 秒保存未完成会话；系统休眠或长时间 tick 中断后自动暂停，不把离线时间算入专注。
- JSON 原子写入并保留最近三份滚动备份；记录目录切换前先验证可写性。
- 支持 Windows 用户启动项与 macOS 登录项；透明花藤本身不申请屏幕录制权限。

## 项目结构

```text
VineFocus/
├── assets/botanical/           # 四套兼容底图与 organs/ 下的 52 个正式器官
├── main.py                     # 应用入口与单实例启动流程
├── pyproject.toml              # 版本、依赖和代码检查配置
├── requirements.txt            # 运行依赖
├── tests/test_smoke.py          # 花藤、状态、窗口和单实例冒烟测试
└── vinefocus/
    ├── config.py               # 场景、任务、界面主题和植物主题配置
    ├── models.py               # 跨模块数据模型
    ├── state.py                # 设置、会话、JSON/Markdown 与备份
    ├── styles.py               # 三套界面主题的视觉令牌和 QSS
    ├── visual_profiles.py      # 三种布局的稳定生长路径规格
    ├── botanical_assets.py     # 高清资产定位、透明器官变换与兼容预览
    ├── overlay.py              # 生长路径、节点年龄与细分器官合成
    ├── widgets.py              # 提示条、统计卡和迷你计时器
    ├── dialogs.py              # 产出记录与成长看板
    ├── settings_dialog.py      # 计时、外观、行为与数据设置
    ├── panel.py                # 主面板与计时/产出业务流程
    ├── tray.py                 # Windows 托盘与 macOS 菜单栏
    ├── single_instance.py      # 单实例检测与窗口唤醒
    └── platform_integration.py # 启动项、应用标识和平台能力
```

每个手写 Python 文件顶部均写明职责。`assets/botanical/organs/` 是正式植物资源，必须随发布包一起分发；旧版 `asset_catalog.py` 和超大的 `resources_rc.py` 不再使用。

完整产品规则见《花藤专注_完整项目需求说明书.md》，接手开发、测试和发布流程见《花藤专注_项目交接文档_v1.7.3.md》，发布前复核结论见《发布前审查报告_v1.7.3.md》。

## 运行与测试

Windows PowerShell：

```powershell
cd D:\Projects\VineFocus
python -m pip install -r requirements.txt
python main.py
python -m unittest discover -s tests -v
```

macOS Terminal：

```bash
cd /path/to/VineFocus
python3 -m pip install -r requirements.txt
python3 main.py
python3 -m unittest discover -s tests -v
```

## 打包建议

Windows 先验证目录版，再生成单文件版：

```powershell
pyinstaller --noconsole --onedir --name VineFocus --add-data "assets;assets" main.py
pyinstaller --noconsole --onefile --name VineFocus --add-data "assets;assets" main.py
```

macOS 应在真实 Mac（推荐 Apple Silicon）上生成 `.app`：

```bash
pyinstaller --windowed --onedir --name VineFocus --add-data "assets:assets" main.py
```

对外发布前，Windows 需要可信代码签名；macOS 需要签名与公证。不能在 Windows 上完成可靠的 macOS 打包与真机验收。

## 实机验收重点

- Windows 11 的 100%、125%、150%、200% 缩放，以及双屏不同 DPI、拔插副屏。
- 连续执行托盘隐藏/恢复 50 次，确认窗口尺寸、位置、透明度和迷你计时器没有漂移或重复。
- 让 30 秒演示自然结束：关闭记录窗口应停留在“待记录”；选择“目标有推进”应推动开花阶段，选择“只是保持了专注”仍应保留本轮枝叶成长。
- 专注与休息都测试暂停、继续、重置/跳过休息；休息结束不得自动开始下一轮。
- 运行中锁屏或睡眠后恢复，确认本轮暂停且离线时间没有计入。
- 四套植物 × 三种布局 × 低/中/高三个代表密度，检查中央工作区、任务栏、Dock 和菜单栏不被遮挡；再拖动密度滑块确认连续变化。
- macOS 真机检查菜单栏入口、Retina/外接屏、多个 Space、Command+Q、通知拒绝与允许两种状态。
